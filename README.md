# P2P Exchange Telegram Bot

Telegram бот для P2P обмена USDT на RUB с системой ролей, управлением сделками и автоматическим обновлением курсов.

## 📋 Общее описание проекта

Бот предназначен для организации peer-to-peer обмена криптовалюты USDT на российские рубли через банковские карты и СБП. Система обеспечивает безопасный обмен с использованием страховых депозитов, системы подтверждения сделок и механизма разрешения споров.

### Основные функции:
- **Авторизация через токены** - безопасный доступ к системе
- **Три роли пользователей** - Owner, Operator, Trader с разными правами доступа
- **Управление реквизитами** - добавление банковских карт и СБП
- **Создание и отслеживание сделок** - полный цикл обработки заявок
- **Автоматическое обновление курса** - парсинг курса с Rapira.net
- **Система споров** - разрешение конфликтных ситуаци
- **Статистика и аналитика** - подробная отчетность по сделкам
- **Планировщик задач** - автоматическая проверка истекших сделок

### Компоненты системы

1. **Bot Core (main.py)** - инициализация бота, настройка диспетчера, запуск планировщика
2. **Handlers** - обработка команд и callback-запросов от пользователей
3. **Services** - бизнес-логика (авторизация, сделки, курсы)
4. **Database** - работа с PostgreSQL через asyncpg
5. **Middlewares** - проверка прав доступа перед выполнением команд

7. **Scheduler** - фоновые задачи (проверка сделок, обновление курса)

- Отслеживание активных заявок

- Управление активными заявками
- Участие в разрешении споров
- Просмотр личного кабинета

- `amount_rub` - сумма в RUB

- `created_at` - дата создания
- `expires_at` - дата истечения

#### disputes
Споры по сделкам

- `opened_at` - дата открытия

## ⚠️ Решение проблем при запуске

### Ошибка множественных экземпляров бота (TerminatedByOtherGetUpdates)

**Проблема**: При запуске бота возникает ошибка:
```
aiogram.utils.exceptions.TerminatedByOtherGetUpdates: Terminated by other getupdates request; make sure that only one bot instance is running
```

**Причина**: Эта ошибка возникает, когда запускается второй экземпляр бота, в то время как первый еще работает. Telegram API позволяет только одно активное polling-подключение для каждого бота.

**Решение**: В текущей версии бота реализована защита от запуска множественных экземпляров:

1. **Автоматическая проверка при запуске**: Бот создает файл `bot.pid` с идентификатором процесса (PID)
2. **Проверка существующего процесса**: При каждом запуске бот проверяет, существует ли процесс с PID из файла
3. **Блокировка запуска**: Если процесс существует, бот не запускается и выводит сообщение с инструкциями

**Если бот завис и нужно принудительно запустить новый экземпляр:**

1. Найдите PID запущенного процесса:
```powershell
tasklist | findstr python
```

2. Завершите процесс:
```powershell
taskkill /F /PID <PID_процесса>
```

3. Удалите файл `bot.pid` (если он остался):
```powershell
del bot.pid
```

4. Запустите бота:
```bash
python main.py
```

**Примечание**: Файл `bot.pid` автоматически удаляется при корректном завершении бота. Если бот был завершен некорректно (например, через Ctrl+C или аварийно), файл может остаться и его нужно удалить вручную.

### Ошибка подключения к Telegram API (ClientConnectorError)

**Проблема**: При запуске бота возникает ошибка:
```
ClientConnectorError: Cannot connect to host api.telegram.org:443 ssl:default [Превышен таймаут семафора]
```

**Причина**: Эта ошибка возникает по следующим причинам:
1. Telegram API заблокирован в вашем регионе (например, в РФ)
2. Брандмауэр или антивирус блокирует соединение
3. Проблемы с DNS-резолвингом
4. Ограничения Windows на количество TCP-соединений

**Решение 1: Использование прокси**

1. Получите рабочий прокси-сервер (HTTP/SOCKS5)
2. Добавьте прокси в файл `.env`:
```env
PROXY_URL=http://proxy.server:port
# или для SOCKS5:
# PROXY_URL=socks5://proxy.server:port
```

3. Перезапустите бота:
```bash
python main.py
```

**Решение 2: Использование VPN**

Если прокси недоступен, используйте VPN для обхода блокировок:
1. Запустите VPN-клиент
2. Убедитесь, что VPN работает (проверьте доступ к api.telegram.org)
3. Запустите бота

**Решение 3: Изменение DNS-серверов**

Иногда проблема в DNS-резолвинге. Измените DNS на публичные:
1. Откройте "Панель управления" → "Сеть и Интернет" → "Центр управления сетями"
2. Нажмите правой кнопкой на ваше подключение → "Свойства"
3. Выберите "Протокол Интернета версии 4 (TCP/IPv4)" → "Свойства"
4. Установите "Использовать следующие адреса DNS-серверов":
   - Предпочитаемый DNS: `8.8.8.8` (Google DNS)
   - Альтернативный DNS: `1.1.1.1` (Cloudflare DNS)
5. Перезапустите бота

**Решение 4: Проверка подключения к Telegram API**

Выполните следующие команды в PowerShell для диагностики:

```powershell
# Проверка DNS-резолвинга
nslookup api.telegram.org

# Проверка соединения (PowerShell 7+)
Test-NetConnection -ComputerName api.telegram.org -Port 443

# Или через curl (если установлен)
curl -I https://api.telegram.org
```

Если соединение не устанавливается, проблема в блокировке или настройках сети.

**Решение 5: Настройка Windows Firewall**

Добавьте исключение для Python и вашего бота:
1. Откройте "Панель управления" → "Система и безопасность" → "Брандмауэр Защитника Windows"
2. Нажмите "Разрешение взаимодействия с приложением в брандмауэре Защитника Windows"
3. Нажмите "Изменить параметры" (требуются права администратора)
4. Найдите Python в списке или нажмите "Разрешить другое приложение"
5. Добавьте python.exe и разрешите доступ для частной и публичной сети

**Решение 6: Увеличение лимита TCP-соединений в Windows**

Для Windows можно увеличить лимит соединений через реестр:
1. Откройте редактор реестра (Win+R, введите `regedit`)
2. Перейдите к `HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\Services\Tcpip\Parameters`
3. Создайте или измените параметр `TcpNumConnections` (тип REG_DWORD) со значением `65534`
4. Перезагрузите компьютер

**Примечание**: Будьте осторожны при редактировании реестра. Создайте резервную копию перед изменениями.

**Решение 7: Проверка антивируса**

Отключите временно антивирус и проверьте, запустится ли бот. Если да, добавьте исключение для папки проекта в настройки антивируса.

### Ошибка семафора на Windows (устаревшее решение)

**Проблема**: В старых версиях могла возникать ошибка `OSError: [WinError 121] Превышен таймаут семафора`.

**Решение**: В текущей версии бота используется правильное закрытие сессии:
```python
session = await bot.get_session()
await session.close()
```

### Устаревший метод закрытия сессии

**Проблема**: DeprecationWarning `Call to deprecated function session (Client session should be created inside async function, use 'await bot.get_session()' instead).`

**Решение**: Заменен устаревший метод `await bot.session.close()` на правильный способ для aiogram 2.x:

```python
session = await bot.get_session()
await session.close()
```

### Обработка сетевых ошибок

Добавлена обработка исключений NetworkError для корректного отображения ошибок подключения к Telegram API:

```python
try:
    await dp.start_polling()
except NetworkError as e:
    logger.error(f"❌ Ошибка сети: {e}")

except Exception as e:
    logger.error(f"❌ Неожиданная ошибка: {e}")
```

4. **Порт занят** - Если порт 5432 занят, измените DB_PORT в .env

## 🔐 Безопасность

### Система токенов
- Каждый пользователь получает уникальный 16-символьный токен
- Токены привязаны к ролям (owner, operator, trader)
- Только активные токены позволяют доступ к системе
- Владелец может создавать и удалять токены

### Проверка доступа (Middleware)
- AccessMiddleware проверяет права перед выполнением команд
- Трейдеры без подтвержденного депозита имеют ограниченный доступ
- Деактивированные пользователи не могут использовать функционал
- Системные команды (/start, /logout) доступны всегда

### Страховой депозит
- Трейдеры обязаны внести страховой депозит (1000 USDT по умолчанию)
- Депозит переводится на кошелек владельца (USDT TRC-20)
- Владелец подтверждает депозит и активирует трейдера
- До подтверждения депозита функционал трейдера ограничен

### Валидация данных
- Номера карт проверяются алгоритмом Луна
- Номера телефонов проверяются по формату РФ
- Суммы проверяются на корректность и диапазон

## 🔄 Жизненный цикл сделки

1. **Создание**: Оператор создает заявку с суммой в RUB
2. **Подбор реквизита**: Система автоматически подбирает подходящий реквизит трейдера
3. **Ожидание оплаты**: Клиент переводит деньги на реквизиты (30 минут)
4. **Подтверждение**: Трейдер подтверждает поступление средств
5. **Завершение**: Сделка помечается как confirmed
6. **Спор** (опционально): При проблемах оператор может открыть спор

## 📊 Статусы сделок

- **pending** - Заявка создана, ожидает оплаты
- **confirmed** - Сделка подтверждена трейдером
- **expired** - Время истекло, оплата не поступила
- **disputed** - Открыт спор
- **rejected** - Сделка отклонена

### Стратегия Wake-on-Webhook

Render free tier "засыпает" через 15 минут неактивности. Чтобы бот отвечал мгновенно:

1. **Health Check Endpoint** (`/health`):
   - Render пингает этот endpoint каждые 30 секунд
   - Это поддерживает бота в активном состоянии
   - Возвращает "OK" если бот работает

2. **Telegram Webhook**:
   - Когда пользователь отправляет сообщение боту
   - Telegram отправляет webhook запрос на Render
   - Это мгновенно "будит" бота
   - Бот обрабатывает сообщение и отвечает

3. **Результат**:
   - Бот всегда готов к работе
   - Задержка ответа: < 2 секунды
   - Бесплатно 24/7

### Решение проблем

#### Бот не отвечает
1. Проверьте логи в Render Dashboard
2. Убедитесь, что `BOT_TOKEN` правильный
3. Проверьте подключение к Neon (`DATABASE_URL`)
4. Убедитесь, что health check проходит

#### Ошибка подключения к БД
1. Проверьте connection string Neon
2. Убедитесь, что `?sslmode=require` добавлен в конец URL
3. Проверьте, что проект Neon активен

#### Бот часто "засыпает"
1. Уменьшите интервал health check до 10-15 секунд
2. Убедитесь, что webhook настроен корректно
3. Рассмотрите платный tier Render ($7/мес) для гарантированной работы 24/7
